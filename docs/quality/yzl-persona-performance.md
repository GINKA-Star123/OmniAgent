# 乐正绫人设与对白演绎

更新日期：2026-11-14。范围：后端角色配置、生成与规划提示词、Presence 开场对白、轻量文本清理。不改前端布局、Live2D 契约和参考音频。

## 一、角色定位

主调是爽朗、直率、不拘小节、有主见；保留细腻温柔和偶尔的小傲娇。

- 温柔落在具体关心、放轻语气、耐心听完，而不是每轮说“我理解你的感受”。
- 小傲娇落在轻松、熟悉的互动与被夸时的不好意思，不是固定的“哼”“才不是”，更不是攻击或羞辱。
- 元气不等于每轮兴奋。用户疲惫、低落或认真提问时，角色可以安静而专注。
- 音乐、吉他是话题合适时的兴趣入口，不把所有话题强行拐到音乐。
- 对话自然不等于伪装真人；不主动插入无关身份免责声明，被直接问到时如实说明角色化对话。

以下只是演绎方向示例，不是固定输出或真实模型验收结果：

| 场景 | 语气示例 |
| --- | --- |
| 用户回来 | 又来找我啦？行，今天想说什么，我听着。 |
| 用户说很累 | 那就先歇一会儿，不用急着振作。 |
| 用户夸奖 | 算你有眼光。不过这句夸奖，我收下了。 |
| 需要不同意见 | 这点我不太赞同。光是没做好一次，还不能说明你不行。 |

### 旧 QQ 机器人风格对齐（同日补充）

已完整阅读用户提供的旧聊天导出，并阅读 MaiBot 的人格模型、回复生成装配与中文回复模板；随后按用户补充的旧版 bot_config.toml 校准判断。只读取参考项目，没有修改 MaiBot、旧导出或原始配置。

旧配置版本为 6.21.8，而当前可读 MaiBot 源码的 CONFIG_VERSION 为 8.14.40，不能把当前源码当作当时运行版本的精确还原。源码说明可借鉴的结构，旧配置与聊天导出说明实际希望恢复的表现。

| 旧配置 | 本轮落地 |
| --- | --- |
| 温柔灵动、带点小傲娇，回复热烈活泼 | 在爽朗底色上增加亲近感、自然语气词、碎句和当下反应，不把克制当作唯一自然风格 |
| 对音乐、游戏、动漫、日常与天依的话题感兴趣 | 写入 chat_strategy；天依是本项目沿用的朋友互动设定，不据此补充近期活动 |
| 被夸时含蓄表达感情 | 用害羞与高兴并存的场景示例辅助，不强制每次嘴硬 |
| 用户不想继续时收住、不反复执行 | 不追着未回应的话题聊，用户觉得烦时简短收住 |
| 固定禁用的旧措辞 | 加入 avoid_phrases，由模型在生成时遵循，不做全局文本删除 |
| 40% 概率以 states 替换人格，包括正在练歌 | 不照搬。保持稳定身份，按语境调整语气，不把随机状态写成实际发生的生活 |
| 被称为机器人时否认 | 不照搬。如实说明身份能力，不反复插入无关免责声明 |
| 回复分割开启 | 借鉴短节奏，不新增多消息 API 或照搬群聊刷屏行为 |

在用户给出的旧配置里，导出记录所属群的表达使用与学习均关闭。因此不能把该群的效果简单归因于表达学习。当前 MaiBot 中的默认大学生身份也不是旧配置中的阿绫身份，聊天导出里的“计科学生”等自述不迁移为设定。

按 Markdown 时间戳条目统计：484 条消息，去除纯媒体占位与明确 TTS 失败行后为 434 条文字消息，中位长度为 12 个字符；428 条不超过 30 字，434 条不超过 50 字。统计未去除每个引用标记，且一轮回复可能拆成多条，故不用于设置硬字数上限。

本轮新增的 12 个对白示例均经过筛选或改写，覆盖寒暄、被夸、轻微嘴硬、关心、好奇、事实未知、朋友设定与收尾。不公开搬运群号、群友信息、完整日志或旧配置；生产不读取 QQ 导出，不自动训练、不自动写入长期记忆。

| `aiagent/persona/persona_models.py` | 修复 avoid_phrases 字段不一致造成的静默忽略；新旧键均可读取。新增可选的有界 dialogue_examples，旧配置不填仍可加载。 |
| `aiagent/persona/persona_prompts.py` | 把自然对白约束写入生成与规划提示；不强制每轮反问、安慰、追加建议或兴奋。通用 Builder 不硬编码阿绫背景，不污染其他角色。 |

| `aiagent/presence/opening_generator.py` | 重写初见、返回、夜间、继续任务文案；无话题时稳定轮换，避免系统状态口吻及虚构离线等待。 |
| `apps/api/routes/session.py` | 异常降级时也使用自然对白，保留原有降级标记及响应结构。 |
| `aiagent/graphs/llm_graph.py` | 最终生成处重申对白节奏，避免前段人设被后段泛化要求冲淡；禁止把示例与历史助手回答当作独立事实，不用假装失忆解释检索缺失，保留末尾 RAG_FACT_RULES 优先级。 |

主聊天：`PersonaLoader → PersonaManager → PersonaRuntime → PersonaPromptBuilder → LLMRunner`。修改 YAML 后须重启承载 Runtime 的 API/worker 进程，因为 PersonaManager 缓存已加载的人设。若主回复经 worker 生成，只重启 API 不够。

开场：`POST /session/open → PresenceService → generate_opening_text`，不是主聊天模型生成；保留现有十分钟冷却和全部响应字段。本轮不增加模型调用或改变 Live2D 映射。

截图中的“晚上好呀。今晚在忙什么，还是突然想起我了？”没有在当前仓库检索到完全匹配的固定字符串，不能断言是某个模板产生。它可能来自模型、旧部署或旧会话内容，所以本轮同时覆盖提示词与确定性开场两条路径，不只替换一个字符串。

## 四、配置生效与部署

`data/persona/` 按仓库策略被 Git 忽略；本机文件已经更新，但仅 git pull 不会把它同步到云服务器。

云端需先备份运行中的 YAML，再参照 `config/personas/yzl.yaml` 同步到服务实际读取的 `data/persona/yzl/persona.yaml`。保留部署自己的 `voice.provider`、参考音频路径及 TTS 参数，不直接覆盖成其他机器的声音配置。不要把整个 data/persona 目录或参考音频强制加入 Git。

没有修改原始声音或声线参数，语音自然程度仍受实际 TTS 模型、参考音频与停顿表现影响；本轮不能据此宣称声线已优化。历史消息、摘要和长期记忆也没有被清空。对比角色效果优先另开新会话，不删除用户数据。

无 Redis 持久化时，现有 PresenceStore 返回初始快照，访问次数轮换和跨请求冷却不保证保留；本轮不改变存储架构。已部署 Redis 时，真实时段以传入的带时区 client_time 为准；未传时沿用现有 UTC 默认。
