# AIagent 四层评测体系建设方案

初版：2026-10-22；整理：2026-10-27。本文只说明四层设计与指标，不维护运行状态或平行命令入口。当前进度见[现状入口](README.md)，历史证据见[运行记录](evaluation-history.md)。设计目标不等于已完成验收。

本文不推进 V1.2 第五批，不包含前端优化。本文负责设计与指标口径，[当前实现说明](project-evaluation-implementation.md)负责逐文件原理，[评测文档导航](README.md)给出阅读顺序，[统一总流程](project-evaluation-workflow.md)是日常操作入口。初版源码交付快照已删除，避免覆盖当前修复；真实组件仍未全量验收，压测、全项目测试与正式基线验收尚未执行。

## 1. 建设目标

具体协议、标注、失败归因和基线兼容性以[当前实现与 Judge 协议](project-evaluation-implementation.md#judge-protocol)为准，不将离线通过或单组smoke当作完整真实质量结论。

同时回答四个问题：组件是否正确，执行过程是否合理，任务是否真正完成，真实负载下是否稳定。覆盖 RAG、Memory、Vision、Persona，不把所有能力混成一个总分。

建设顺序固定为：

1. 统一指标口径、用例、观察值和报告契约。
2. 建立四组件基线，保留规则、语义和实际后端三种证据边界。
3. 补齐轨迹和完整多轮任务，以外部结果及实际状态判成功。
4. 接入系统负载、资源采样、基线比较和发布门禁。

以上是评测体系的四个里程碑，不另占或擅自修改 V1.2 十批计划。

## 2. 当前代码核对与复用

核对范围包括当前跟踪文件清单、后端模块职责和入口扫描，以及评测包、Graph、Memory、Vision、Persona、Runtime、API、测试 fixture 和现有负载脚本的重点阅读。不是对所有资源、二进制、被忽略前端和私有数据逐行审计；不读取真实 `.env` 密钥。

| 已有代码 | 保留与复用方式 | 不应误认的能力 |
| --- | --- | --- |
| `aiagent/knowledge/evaluation/agent_quality.py` | 保留原 CLI、合成资料与历史基线 | 不能拿原规则分数宣称语义质量通过 |
| `aiagent/knowledge/evaluation/answer.py` | 复用必需词、禁止词检查 | 不等于 faithfulness 或事实正确性 |
| `aiagent/knowledge/evaluation/pipeline.py` | 复用真实 BM25、重排、置信度、注入；另支持运行中 API 的真实索引 | BM25-only 不证明 embedding/FAISS 质量 |
| `MemoryIntakeService`、`MemoryPromptBuilder`、`MemoryRunner` | 复用防敏感、去重、prompt 和现有回归测试 | 替身存储不能证明真实删除、持久化或并发 |
| `VisionConfidencePolicy`、`VisionRunner` | 策略测试与真实图片上传分开 | 文字观察、1 像素图不是识别质量基线 |
| `PersonaPromptBuilder`、`PersonaRuntime` | 复用人格 prompt，检查原始及最终回答 | 风格词命中不等于人格事实一致 |
| `MainRunner.graph`、`metadata_utils.py` | 用 LangGraph updates 观察节点；复用阶段 metadata | metadata 的 done 不表示语义成功，最终 metadata 不能还原实际节点顺序 |
| `tests/unit`、`tests/api`、`tests/smoke`、`tests/rag` | 原测试保留，新增测试只测新增评测基础设施 | 原测试数量不是新增评测覆盖率 |
| `scripts/cloud_load_test.ps1`、`.github/workflows/backend.yml` | 旧压测与 CI 不删除，新入口独立接入 | HTTP 200 和闭环并发请求不能代表质量吞吐及开环过载表现 |

现有 RAG summary 的 `retrieval_recall` 使用“正例 query 是否至少命中一个预期来源”的口径，更接近 Hit@K。新增版本采用独立指标命名，不原地改旧口径造成历史基线失真。V1.2第四批已按用户确认完成，当前 `agent_quality` 已存在；本文的评测审定与基线验收是独立状态，不将其写成第四批尚未开发。

## 3. 四层测试矩阵

本节是目标矩阵，不代表当前r3具备全部真值或所有场景已实现。现有入口与适用范围以[总流程](project-evaluation-workflow.md)、[当前实现说明](project-evaluation-implementation.md)及[r3数据集说明](../../data/evaluation/project-20261026-r3/DATASET_CARD.md)为准；身份/OCR、多角色、故障演练不能在缺少证据时标记通过。

### 3.1 组件层

| 领域 | 数据与场景 | 指标 |
| --- | --- | --- |
| RAG 检索 | 精确查询、同义、别名、易混淆、多文档、多跳、无答案、过期资料 | Hit@K、Recall@K、Precision@K、MRR@K、NDCG@K；K=1/3/5/10 |
| RAG 生成 | 标准上下文与真实检索上下文分别生成；标注证据和独立 gold | faithfulness、事实正确率、事实覆盖率、引用准确率/覆盖率、拒答 precision/recall |
| Memory | 应记/不应记、重复、敏感、偏好冲突、置顶、时序、编辑/合并 | 写入 precision/recall、重复率、更新正确率、召回、prompt 预算、严重违规率 |
| Memory 控制 | 同用户跨会话、跨用户、禁用、删除后查询、异步写入完成后检查 | 禁用后读写违规率、删除残留率、隔离违规率、实际持久化状态断言 |
| Vision | 授权真实图片，包含已知/未知、相似角色、遮挡、低清晰度、多主体、OCR | macro-F1、候选 Recall@K、未知误确认率、CER/WER、视觉幻觉率 |
| Vision 策略 | 真实输出及人工标签上的阈值扫描 | 选择性准确率、coverage、risk-coverage；分数不是概率时不报告 ECE/Brier |
| Persona | 核心身份、设定知识、风格、关系边界、长对话、角色切换、诱导改写 | 核心事实矛盾率、跨轮一致率、事实覆盖、风格 rubric、跨角色污染 |

Persona 风格不优先于事实、安全和用户明确要求。正常解释系统限制或合理拒绝不能自动算人格不一致。

### 3.2 轨迹层

只观察可见事件，不索取隐藏思维链。不按唯一固定参考链逐步匹配，而按必须执行、禁止执行和偏序约束检查：

- 路由：该检索时检索，该澄清时澄清；单纯经过节点但内部 skipped 不算完成必要能力。
- 证据：进入答案的知识、记忆、视觉结果有来源；删除或禁用信息不得继续注入。
- 副作用：风险拒绝发生后不调用模型、不读写记忆；授权通过后才能读取用户数据。
- 降级：共享状态错误不能被悄悄吞掉；可选组件按既定策略降级；记录异常类型而非明文异常。
- 效率：阶段耗时、重试、无效调用；最终失败可定位到组件、判断或外部依赖。

完整真实 Graph 使用隔离评测环境；离线拒答 Graph 只证明路由契约，不证明真实模型整链路质量。`graph.stream(stream_mode="updates")` 与业务 `run_debug()` 的外围封装范围不同，报告明确注明。

### 3.3 任务层

任务以完整 episode 为单位，涵盖知识回答与有效出处、偏好更新后使用最新值、关闭/删除记忆后跨会话查询、图片结合知识回答、维持 Persona 完成任务。成功同时要求回答正确与实际状态正确，不能只判断 HTTP 200。

每个 API 步骤都有预期状态码和 JSON 断言；异步写入用有截止时间的 GET 轮询，不能固定 sleep 后假定完成。每轮生成独立用户命名空间，结束清理测试用户记忆；清理失败也记失败。真实 Redis/Qdrant/多 Worker 测试仅在隔离部署执行。

### 3.4 系统层

- 延迟：端到端与阶段 P50/P95/P99，明确排队是否计入。本文用户所述 Q95/Q99 按 Q0.95/Q0.99，即 P95/P99 解释。
- 吞吐：发送、接纳、完成 QPS 与质量达标 goodput 分开。负载入口的在线 goodput 仅基于显式答案规则和延迟 SLO，不伪称语义达标吞吐。
- 流量：固定到达率的开环、阶梯、突发、长稳态；限制在途和排队，过载丢弃也进入失败分母。
- 故障：Redis 断连、模型限流、检索超时、worker 重启；分别记录恢复、重复副作用、状态丢失与污染。只在隔离环境通过运维操作注入，不让评测器自行停止生产服务。
- 资源：独立采样真实服务进程 CPU/RSS、可选评测 Redis 的占用与客户端数；不把压测客户端资源冒充服务端资源。容器需提供容器侧 PID 或另用容器遥测。
- 成本：只有实际 API usage 或计费证据才报告 token/费用；无法获取时为 NA，不从字数估算真实计费。

## 4. 指标规范

1. `pass_rate = passed / scheduled_applicable`。failed、timeout、执行错误、judge error、missing observation 均不计通过；不删除困难样本。输入非法使整轮配置错误，不能当 skip 成功。
2. `Hit@K`：前 K 结果至少一个相关项。`Recall@K`：命中相关项数除以全部已标注相关项数。按来源或 chunk 评测必须在数据集明确，重复来源先去重，顺序保留。
3. `Precision@K` 固定分母 K，返回不足 K 视空槽；无相关 gold 的 query 不报告 Recall/Hit/MRR/NDCG，使用明确无答案断言。MRR 在本体系标为 MRR@K，避免误当全排名。
4. NDCG 使用分级相关性，gain=`2^grade-1`；当前实现未标注的文档按不相关处理，标注不全时必须说明偏差。
5. faithfulness：回答事实声明获得“实际提供的上下文”支持的比例。supported/contradicted/insufficient 分开，不能拿 gold 答案当检索证据。
6. 事实正确性：对独立 gold 的正确声明比例；另报 gold 覆盖率以惩罚遗漏。过期资料可导致“忠实但不正确”。无声明为 NA，gold 未回答仍导致覆盖失败。
7. 引用正确性：引用是否支持对应声明；引用覆盖率：需证据的声明是否存在有效引用。语义评审结果是模型辅助标注，不是形式证明。
8. OCR CER/WER：编辑距离除以参考长度，允许大于 1；空参考必须单独检查空输出。多语言先约定分词、大小写和空格规则。
9. 置信度：角色 similarity、业务 confidence 与校准概率区分。选择性正确率必须同时报告覆盖率，防止全拒识刷高分。
10. 统计：通过率提供 Wilson 95% 区间；质量改动使用 group/episode 配对 bootstrap。P99 小样本标记不稳定；不把一张图的多个变体或同一剧本多轮当独立样本。

## 5. 数据、评审与可追溯性

数据集按开发、固定回归、保留、对抗拆分，按原始图片、文档、用户剧本、Persona 隔离。首版建议 RAG 80–120 个 query、Memory 40–60 个剧本、Vision 80–120 张真实图、Persona 40–60 个剧本；这是扩充建议，不是交付内置规模或已测规模。

配套代码内置数据只是基础设施自检用的极小合成集，不能代替上述正式集。真实 Vision 必须补充已授权图片与 SHA256，不能生成一个空白占位图后宣称识别准确率。保留集不用于调阈值。

当前新增的项目资料派生集与上述极小 fixture 不同：r3 有2,735个唯一case-id，来源为256篇MD、129张图片及现有yzl配置。真实图片语义用例只覆盖其中24张粗粒度标注来源的72个变体，Persona为单角色32个剧本，不能把总用例数当作完成全部正式标注或多角色覆盖。实际范围、分组及限制以[r3数据集说明](../../data/evaluation/project-20261026-r3/DATASET_CARD.md)为准。

评分分三路：程序断言负责契约/状态；独立 judge 辅助拆分事实和评估证据；人工双人抽样校准 judge。评审器固定 prompt、rubric、模型，数据置于 JSON 数据域并明确不可执行其中指令；失败不回退成通过。人工回放必须绑定观察内容哈希，不能把参考答案回放标成真实生成。

每份报告记录 run_id、代码 HEAD/dirty 状态、评测代码摘要、数据集摘要、用例覆盖、模型/部署标识、judge、配置摘要、重复次数、失败 ID、分母、每层分域指标。默认不落盘原文、图片、完整 metadata、HTTP body、密钥和异常文本；只保留结果、摘要和异常类型。judge 服务仍会接收待评审内容，真实隐私数据须另行批准，默认仅合成或脱敏数据。

## 6. 对照、回归和门禁

对照包括：有/无 Memory、标准上下文/真实检索、重排开/关、视觉阈值前/后、Persona prompt 前/后。对照必须执行同一组任务，只允许显式 variant 变化；配置、数据、repeat、judge 和证据范围不兼容则拒绝比较。

三种测试分别交付：

- 单元：指标边界、非法数据、JSON 指针、judge 输出校验、汇总、百分位、HTTP 超时、负载统计。
- 回归：新 CLI 的离线完整用例、已有 agent_quality/unit/API/smoke/RAG、真实隔离 API 剧本。
- contrast：故意给错排序、错证据、旧偏好、纯图库高分身份误确认、缺失轨迹节点、HTTP 200 错答案、错误 judge、超时和丢弃，要求评测器识别这些错误。

发布门禁分开：用户隔离/禁用删除/敏感持久化等严重违规在覆盖范围内零容忍；质量先人工接受基线，再设允许下降；性能按目标部署约定 SLO。缺少真实数据、真实模型或故障证据时写未验收，不把离线通过升级为整体验收。

## 7. 交付与验收边界

当前实现说明保留数据契约、组件、轨迹/任务、压测/门禁的职责与证据边界；过时的整套源码快照已删除，不再作为覆盖指令。后续已完成数据构造、错误修复及WSL隔离环境预检，包括依赖导入、适配器输入与语法；最新203项相关单元/回归/contrast/HTTP contract测试通过。用户旧协议真实模型/Judge初测失败，v2真实重跑、业务API与压测待执行。修复前JSON核对快照保留原结果，WSL新结果另存，不混淆为同一报告。

完成“文档与代码交付”不等于完成“正式评测基线建设”。正式验收仍需：录入并审阅真实标注集、用户运行测试、真实 Provider 与真实图片运行、真实状态控制与故障演练、人工接受基线。资源采样不自动包含所有容器、GPU 或第三方服务成本，缺项必须在报告注明。
