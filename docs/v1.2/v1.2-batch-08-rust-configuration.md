# V1.2 第八批 Rust 配置与运行说明

本文与 [第八批代码交付](v1.2-batch-08-code-delivery.md) 配套。本文只解释安装、构建、配置和排障；Rust/Python 源码以代码交付文档为准。所有命令均需你在目标环境手动执行，本次未安装工具链、编译、联网或运行容器。

## 1. 组件定位

`security/context-guard` 是由 Python 服务启动的本地 Rust 子进程，不是 HTTP 服务，不需要开放端口。它通过标准输入接收单个 JSON，标准输出返回一次裁决。Rust 处理版本、大小、来源、用途、内容摘要和有限风险信号；Python 负责主体、超时、二进制校验和账本资格。它不识别所有注入、不认证用户、不负责长期记忆批准或进程沙箱。

依赖：第五至七批的受管执行帧、共享账本与批准写入必须已实际实施。当前工作区这些代码部分只存在于交付文档；不要仅凭文档存在就启动本批。

## 2. 工具链与锁文件

代码交付文档使用 Cargo edition 2021、`rust-version = "1.82"`，依赖 serde、serde_json、sha2。`rust-version` 是最低版本，不保证未来最新依赖仍支持该版本。建议在受控构建环境固定经验证的 Rust 工具链，并提交审阅过的 `Cargo.lock`；不要把 `target/` 或编译后二进制作为源码提交。

Windows 使用 MSVC 目标时需要对应的 Visual Studio C++ 构建工具。先检查：

```powershell
rustc --version
cargo --version
rustup show
```

由你先手写代码交付文档中的 `Cargo.toml`、`src/main.rs`，再在项目根目录执行：

```powershell
cargo generate-lockfile --manifest-path security/context-guard/Cargo.toml
cargo test --locked --manifest-path security/context-guard/Cargo.toml
cargo build --release --locked --manifest-path security/context-guard/Cargo.toml
```

首次生成锁文件可能联网，需审阅依赖来源和许可。后续优先 `--locked`；锁文件失效或工具链不支持时应修订并重新审阅，而不是自动降级或换不受控依赖。Windows 本机 release 文件通常在 `security/context-guard/target/release/context-guard.exe`，Linux 是 `context-guard`。

## 3. 服务配置

两个模板 `.env.example` 与 `cloud.tencent.example.env` 按交付文档配置相同键。实际本地及云端分别填各自绝对路径和摘要；`.env`、Token 和真实配置不提交 Git。

| 键 | 作用 | 约束 |
| --- | --- | --- |
| `CONTEXT_GUARD_EXECUTABLE` | 已安装的本机可执行文件绝对路径 | 由运维指定，不接受用户请求覆盖 |
| `CONTEXT_GUARD_SHA256` | 上述可执行文件的 SHA-256 | 64 位小写十六进制；重新构建后必须更新 |
| `CONTEXT_GUARD_PERSONA_SHA256` | 当前部署审阅的 Persona JSON 摘要 | 使用项目 `execution_ledger.digest` 算法，不是普通文件哈希 |
| `CONTEXT_GUARD_TIMEOUT_SECONDS` | 单次审查墙钟超时 | 0.1–5 秒；示例 2 秒，不代表性能基准 |

Windows 计算二进制哈希：

```powershell
$guard = (Resolve-Path security/context-guard/target/release/context-guard.exe).Path
(Get-FileHash -Algorithm SHA256 $guard).Hash.ToLowerInvariant()
```

已完成第五、六批 Runtime 装配后，从服务器当前 Persona 计算与代码完全一致的摘要：

```powershell
.\.venv\Scripts\python.exe -c "from apps.core.runtime_registry import get_runtime; from aiagent.state.execution_ledger import digest; p=get_runtime().dispatcher.persona_manager.get_active_persona().config.model_dump(mode='json'); print(digest(p))"
```

本命令会初始化当前 Runtime，可能触及已配置的本地资源；不要在生产机器上未经运维批准执行。确保选择的是正式审阅过的 Persona，不从用户请求中取摘要。部署变更 Persona 后必须重新审核、更新摘要并重启相关服务。空值或不匹配会使受管请求明确失败，不会切换到未经审查模式。

## 4. Windows 与 Linux 容器

同一套协议不意味着两个平台可以共用一个二进制或摘要。需要针对每个目标操作系统/架构独立构建，并在目标环境测试。Linux 服务器运行时路径示例：`/usr/local/bin/context-guard`。

第八批交付文档给出 Docker 多阶段构建片段：前一阶段构建、最终阶段只复制 release 二进制。实际 `deploy/Dockerfile.api` 和 `deploy/Dockerfile.worker` 先确认已有多阶段名称和构建上下文，再手工加入；保留现有 CPU 依赖、非 root 用户与启动命令。构建阶段使用的 Rust 镜像与最终 Debian 镜像须检查架构和 glibc 兼容性；首次构建成功不等于最终镜像能执行。生产镜像应固定审阅过的 digest。

最小权限：二进制和父目录由管理员管理，运行用户无写权限；不要把整个 `.env`、API Token 或 Redis 连接串传给子进程。Python 适配器只向 Windows 子进程传递启动必需的系统目录变量，Linux 默认空环境。文件哈希检查仍有检查到执行之间被替换的时间窗口，部署只读权限是必需条件；这不是 OS 级沙箱。

## 5. 测试与运行

完成手写并配置隔离环境后，设置实际构建二进制的测试变量：

```powershell
$env:BATCH08_CONTEXT_GUARD = $guard
.\.venv\Scripts\python.exe -m pytest tests/integration/test_context_guard_v8_binary.py tests/integration/test_context_guard_v8_seed_binary.py -q
Remove-Item Env:BATCH08_CONTEXT_GUARD
```

未配置测试路径时相关测试会 skip；配置了错误路径或不可执行文件应失败，不能把 skip 或替身当作真实 Rust 通过。完整离线、API contract、主图和数据测试指令见第八批交付文档。真实 Provider 评测与本地 mock 分开记录，可能付费；本轮不会执行。

## 6. 常见问题

| 现象 | 检查方向 |
| --- | --- |
| `context_guard_configuration_invalid` | 路径是否为绝对路径、摘要是否为 64 位小写十六进制、超时是否在范围内 |
| `context_guard_binary_unavailable` | 文件是否存在、服务账户是否可读、Windows/Linux 文件名是否正确 |
| `context_guard_binary_untrusted` | 文件重新构建后哈希是否更新；目录是否被非授权修改 |
| `context_guard_start_failed` | 是否可执行、CPU 架构和动态链接是否兼容、服务账户权限是否足够 |
| `context_guard_timeout` | 测试进程、机器负载与超时配置；不得因此禁用审查或回退原文 |
| `context_guard_response_invalid` | Python 与 Rust 协议版本是否一致、输出是否截断或被污染 |
| `context_guard_persona_not_deployment_approved` | 当前 Persona JSON 和部署侧摘要是否一致；确认修改经授权后再更新 |
| `context_guard_input_expired` | 操作或观察是否超时、Redis 服务端时间和第六/七批 deadline 是否正常 |

生产部署前需完成真实调用点审计、独立攻击/正常样本、目标镜像测试与真实 Provider 对抗评测；仅有本配置文档和 `cargo test` 不足以证明注入防护有效。

## 7. 评测与环境隔离

第八批总交付文档第 15–18 节包含异常传播、子进程超时回收、来源对照和可选真实 Provider 组件评测代码。需要真实 Rust 二进制的测试由 `BATCH08_CONTEXT_GUARD` 指向当前平台产物；Python 子进程回收测试使用本机解释器，不需要该变量，也不能算 Rust 合同测试。额外的 `tests/integration/test_guard_protocol_v8_binary.py` 也需要真实二进制。

真实 Provider 组件评测还要求 `EVAL_ISOLATED=1`、`--allow-real-provider`、`--accept-cost`，且模型不能是 Mock。必须选择经部署摘要批准的合成 Persona，并在私有目录创建报告；可选原始回答可能含敏感内容，不能提交。该入口在 Prompt 边界构造合成来源，不证明真实 RAG、Memory 和 OCR 数据源已端到端覆盖；生产验收仍需这些数据路径的隔离测试与复核。

超时测试只验证适配器回收其直接子进程；该实现并不提供 Windows Job Object 或 Linux 进程组沙箱。生产 Rust 可执行文件及其目录必须只读且受运维控制，不能替换成能够派生任意子进程的程序。
